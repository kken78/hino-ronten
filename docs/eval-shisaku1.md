## 4. 記録のしかた

- 出力ごとに、日付、場面、生成AIの製品・モデル名・エフォート（分かる範囲）、共通の指示の版、テーマのノートのデータを作った lock と台帳の版を記録する
- 基準ごとに、満たしたか、満たさない点の数と、その箇所を記録する
- 満たさない箇所ごとに、原因を次のどれかに分ける。モデルやエフォートを上げれば良くなる、で片付けない（ADR-13）
  - 資料の欠け：入力にその資料が無い（例：決算の成果資料）
  - 取り出しの欠け：入力にあるが、テーマのノートのデータに入っていない（例：テーマの定義の漏れ、語の一致の取りこぼし）
  - 道具の欠け：MCP の道具で、その資料に辿り着けない
  - 指示の欠け：共通の指示や依頼文が足りない
  - 生成AIの誤り：資料も道具も指示も足りているのに、生成AIが誤った
- 同じ場面を、基盤の中に置く低コストの生成AIと、各自が使う生成AIに近い設定（Claude の標準の設定など）の2つ以上で行い、原因の分け方が同じになるかを比べる。比べるのは、低コストの生成AIで足りるかを見るためで（ADR-12）、足りない箇所の言い訳にはしない
- 記録は build/eval/ に置き（git に入れない）、まとめをこの文書の末尾に日付を付けて足す

## 5. 実行のしかた

- 生成AIは、依頼者の PC の Claude Code を非対話で動かす（`claude -p`）。MCP の道具は `tools/mcp_ronten.py`（LINK_SCHEMA §14）だけをつなぎ、許す道具をその道具だけにする（ファイルの読み書き、命令の実行、ウェブの検索と取得は使わせない）。細かな引数は、実行の指示のときに Claude Code の help で確認して書く
- モデルは2つ：Haiku 5.5（基盤の中に置く低コストの生成AIの代わり）と Opus 5.5（各自が使う生成AIに近い設定）。場面ごと・モデルごとに、新しいセッションで1回ずつ行う
- 共通の指示（`prompts/shisaku1-common-v1.md` の「---」より後）を、依頼文の前に置いて渡す
- 出力は `build/eval/<日付>-<場面>-<モデル>.md` に、MCP の呼び出しの記録は `build/eval/mcp-log.jsonl` に残す（git に入れない）
- 基準の確認のうち道具で行うもの（K1 の出典の有無、K2 の引用の一致、K4 の layer）は、出力と MCP の記録から道具で数える。その道具は、出力を見る前に作る

## 6. 持ち込み用の資料で行うとき（2026-10-29 に足した）

持ち込み用の資料（DESIGN.md ADR-26、LINK_SCHEMA §17）を生成AIに渡すときも、§1 の場面と依頼文、§2 の基準、§3 の大事な事実をそのまま使う。基準は変えない。違うところは次のとおり。

- 共通の指示は `prompts/shisaku1-common-v2.md`（ファイルを添える使い方の版）の「---」より後を使う
- 生成AIに渡すのは、その事業の本編と記録編（.md）だけとする。依頼者の PC の Claude Code を非対話で動かし（`claude -p`）、許す道具を build/rag/ のファイルの読み取りだけにする（命令の実行、ウェブの検索と取得、ほかのファイルの読み書きは使わせない）。細かな引数は、実行の指示のときに Claude Code の help で確認して書く
- K1 の出典は、持ち込み用の資料に書かれた url とする。K4 の未確認は、【未確認】の段落と照合結果（未確認）の節とする。K9 の論点の候補は、照合結果（未確認）の節の文とする
- モデルは §5 と同じく2つ（Haiku 5.5 と Opus 5.5）。出力は `build/eval/<日付>-rag-<場面>-<モデル>.md` に残す（git に入れない）
- 満たさない箇所の原因の分け方（§4）に「持ち込み用の資料の欠け」（データにあるが、持ち込み用の資料に書いていない。書き方が RAG で読みにくい）を足す
- 道具で数えること（§5 のとおり、出力を見る前に作る）：`python3 -B tools/eval_rag.py <出力の .md> <本編の .md> <記録編の .md>`。判定はせず、次を一覧にして build/eval/<出力の名前>-check.md に書く
  - 文の分け方：出力を行に分け、見出し（「#」で始まる行）・空行・区切り線・表の区切りの行を除き、行を「。」で文に分ける（かぎかっこの中の「。」では分けない）。「。」のあとに続く［出典：…］は、その前の文の出典とする
  - K1：出典（［出典：url］。持ち込み用の資料と同じ（出典：url）の形も含める）の無い文。そのうち事実を述べる文かどうかは人が見る
  - K1：出典の url のうち、持ち込み用の資料に無いもの
  - K2：かぎかっこ「」で引いた文（入れ子は外側）のうち、持ち込み用の資料に無いもの。比べるときは NFKC にそろえ、空白を除く。「…」で略してあれば、その前と後をそれぞれ探す
  - K4：出典の url が、持ち込み用の資料では【未確認】の段落か照合結果（未確認）の節にしか無いのに、文に「未確認」の語が無いもの
  - 参考：文の数、出典の付いた文の数、引用の数、出典の url が持ち込み用の資料のどの章にあるか
- K3（数字）・K5〜K8・K10 は人が見る。判定シートは依頼者が判定する（CLAUDE.md 不変の制約11）
- 2026-10-29 の確認は、依頼者の判断で、依頼者の PC ではなくクラウドの作業場所の Claude Code（2.1.312）で行った。持ち込み用の資料は PC で作ったものと sha256 が同じで、条件は変わらない

## 7. 答弁で外せない語の再現性（2026-10-30 に足した）

使い方（依頼者、2026-10-29）：A 答弁を書くとき、これまでの経緯と矛盾して突っ込まれないようにする。B 経緯を正しく要約しながら、広報文などを用途ごとに迷わず書く。まず A について、このテーマで答弁するときに外せない語（正式な名前、根拠の言い回し、数字と時期）を、生成AIが落とさず、言い換えず、何回動かしても同じように入れるかを見る。外せない語は、出力を見る前に依頼者が決める。

### 7.2 数え方
