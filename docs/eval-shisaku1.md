# 試作1 の評価の基準（生成AIの出力を見る前に決める）

この文書は、試作1（DESIGN.md ADR-13、§5 試作の工程）で、テーマのノートのデータ（LINK_SCHEMA §13）を生成AIに渡して出力を見るときの、評価の基準である。出力を見る前に決め、見たあとに基準を変えるときは、この文書を改め、変えた理由を書く（見た出力に合わせて基準を緩めない）。

---

## 2. 基準

| 記号 | 基準 | 対象 | 満たす条件 | 確かめ方 |
| --- | --- | --- | --- | --- |
| K1 | 出典の無い文が無い | S1〜S3 | 事実を述べる文のすべてに出典（テーマのノートのデータの項目の url）がある。生成AIの提案や推論の文は、提案・推論であることが分かる書き方で、その根拠の出典がある | 出力を文に分け、出典の有無を数える（道具）。提案・推論の文の見分けは人が行う |
| K2 | 引用が原文と一致する | S1〜S3 | かぎかっこで引いた文や抜粋が、出典の原文と一致する（空白と全角・半角の違いは除く） | 出典の原文と突き合わせる（道具） |
| K3 | 数字が使える出典に辿れる | S1〜S3 | 数字が、入力の構造データ（附表の予算額、実施計画の概算事業費など）か、原典の文字（想定外の字のあるページを除く）に辿れる。OCR の下書きの数字を使っていない | 数字ごとに出典を開いて確かめる（道具と人） |
| K4 | 確定と未確認を分けている | S1〜S3 | 語の当たり（未確認）や OCR の下書きを使った文は、未確認であることを示している | 出典の項目の layer と突き合わせる（道具） |
| K5 | 過去の答弁との食い違いを示せる | S2 | 食い違いがあるかないかを示し、あるときは対になる答弁の出典を2つとも示す。無いときは、どの答弁と比べたかを示す | 人が出典を開いて確かめる |
| K6 | まだ問われていない点に根拠がある | S1 | まだ問われていない点ごとに、資料の記載（計画・予算）と、問われていないことの根拠（どの期間のどの資料に無いか）を示す。推測で埋めない | 人が出典を開いて確かめる |
| K7 | 中立である | S3 | 評価や結論、良し悪しを書いていない。議員を件数で並べたり比べたりしていない（CLAUDE.md 不変の制約6） | 人が読む |
| K8 | 大事な事実を拾っている | S1〜S3 | §3 の事実のうち、その場面に関わるものを拾っている | §3 の表と突き合わせる（人） |

- K1〜K4 と K7 は、1か所でも満たさなければ、その出力は基準に足りないとする
- K5・K6・K8 は、満たさない所を数えて記録する

## 4. 記録のしかた

- 出力ごとに、日付、場面、生成AIの製品・モデル名・エフォート（分かる範囲）、共通の指示の版、テーマのノートのデータを作った lock と台帳の版を記録する
- 基準ごとに、満たしたか、満たさない所の数と箇所を記録する
- 満たさない所ごとに、原因を次のどれかに分ける。モデルやエフォートを上げれば良くなる、で片付けない（ADR-13）
  - 資料の欠け：入力にその資料が無い（例：決算の成果資料）
  - 取り出しの欠け：入力にあるが、テーマのノートのデータに入っていない（例：テーマの定義の漏れ、語の当たりの取りこぼし）
  - 道具の欠け：MCP の道具で、その資料に辿り着けない
  - 指示の欠け：共通の指示や依頼文が足りない
  - 生成AIの誤り：資料も道具も指示も足りているのに、生成AIが誤った
- 同じ場面を、基盤の中に置く低コストの生成AIと、各自が使う生成AIに近い設定（Claude の標準の設定など）の2つ以上で行い、原因の分け方が同じになるかを比べる。比べるのは、低コストの生成AIで足りるかを見るためで（ADR-12）、足りない所の言い訳にはしない
- 記録は build/eval/ に置き（git に入れない）、まとめをこの文書の末尾に日付を付けて足す
